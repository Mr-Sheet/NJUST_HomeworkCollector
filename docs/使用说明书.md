## 1. 系统简介

这是一个通过链接访问的班级作业收集系统，包含两端：

- **教师端**（首页 `/`）：需输入访问密码登录；发布作业、查看收集进度、下载全部作业、停止/恢复收集、删除作业。
- **学生端**（`/upload/<作业ID>`）：无需密码，查看命名规范，上传符合规范的文件。

核心特点：

| 特性 | 说明 |
|---|---|
| 教师端密码保护 | 管理操作需要密码（默认 `123456`，务必修改，见下文） |
| 学生端免登录 | 学生拿到链接即可提交，靠链接中的作业 ID 保护 |
| 文件名强校验 | 每个作业绑定一个正则表达式，文件名必须**完全匹配**才允许提交 |
| 名单与进度 | 上传班级名单后自动统计 n/m 提交进度和未交名单 |
| 允许重复提交 | 同名文件自动覆盖，以学生最后一次提交为准 |
| 自动截止 | 超过截止时间后学生端自动关闭提交入口 |
| 手动停止 | 教师可随时手动"停止收集"，立即生效 |
| 一键打包 | 将某次作业的所有提交文件打包为 ZIP 下载 |

### 教师端密码

- 默认密码为 `123456`，**上线前请务必修改**。
- 修改方式（二选一）：
  1. 设置环境变量 `TEACHER_PASSWORD`（推荐，Vercel 后台 Settings → Environment Variables 中添加后重新部署即可生效）；
  2. 直接编辑 `app.py` 中的 `TEACHER_PASSWORD` 一行。

## 2. 快速开始（本地运行）

### 2.1 环境要求

- Python 3.9 及以上（推荐 3.10+）
- 无需数据库、无需 Nginx，只用 Flask 一个依赖

### 2.2 安装与启动

```bash
# 1. 进入项目目录
cd NJUST_HomeworkCollector

# 2.（推荐）创建并激活虚拟环境
python -m venv venv
# Windows:
venv\Scripts\activate
# Linux / macOS:
source venv/bin/activate

# 3. 安装依赖（只有一个：Flask）
pip install -r requirements.txt

# 4. 启动
python app.py
```

看到如下输出即启动成功：

```
 * Running on http://127.0.0.1:5000
```

浏览器打开 **http://127.0.0.1:5000** 即进入教师端首页。

### 2.3 修改端口（可选）

默认端口 5000，可通过环境变量修改：

```bash
# Linux / macOS
PORT=8080 python app.py

# Windows (PowerShell)
$env:PORT=8080; python app.py
```

### 2.4 局域网使用（可选）

程序监听 `0.0.0.0`，同一局域网内的设备可直接访问：

```
http://<你的电脑局域网IP>:5000
```

查看本机 IP：

```bash
# Windows
ipconfig        # 看"IPv4 地址"一栏
# Linux / macOS
hostname -I     # 或 ifconfig
```

> 适合教室场景：电脑和手机连同一个 WiFi，学生用手机浏览器即可交作业。

## 3. 教师端使用指南

### 3.1 发布新作业

打开首页 `/`，在"发布新作业"表单中填写：

| 字段 | 必填 | 说明 |
|---|---|---|
| **作业名称** | ✅ | 显示在学生端页面顶部和作业列表中，如"实验一 报告提交" |
| **截止时间** | ✅ | 日期 + 时间选择器，格式如 `2099-01-01 23:59`。以**服务器本地时间**为准 |
| **命名规范** | ✅ | 一个正则表达式，学生的文件名必须与其完全匹配（详见[第 5 节](#5-正则表达式编写教程)） |
| **提交说明 / 示例** | ❌ | 建议填写！会展示给学生，如"正确示例：2024001_张三_实验1.pdf" |

点击 **「发布作业」**，系统会：

1. 生成 12 位唯一作业 ID（如 `a6c5cb3c7bde`）
2. 生成学生端链接：`http://<你的域名>/upload/<作业ID>`
3. 顶部绿色提示条会显示完整的学生端链接

把这个链接发到班级群即可。

### 3.2 管理作业列表

每条作业在列表中显示：名称、ID、正则（代码块样式）、截止时间、状态徽章（开启/关闭/已截止）、已收文件数。

四个操作按钮：

| 按钮 | 作用 | 备注 |
|---|---|---|
| **查看上传页** | 新窗口打开学生端页面 | 用于预览学生看到的样子；注意教师也能通过此页提交文件 |
| **下载全部** | 打包该作业全部已提交文件为 ZIP | 没有收到任何文件时会提示，不产生下载 |
| **停止收集 / 重新开启** | 切换开启 ↔ 关闭 | 关闭后学生端显示"该作业已停止收集"（HTTP 403）；有确认弹窗 |
| **删除** | 删除作业记录 + 全部提交文件 | ⚠️ **不可恢复**，有二次确认弹窗 |

### 3.3 推荐收作业流程

```
发布作业 → 复制学生端链接发到班级群
   ↓
收集期间可随时点"查看上传页"预览，列表中"已收文件"徽章实时显示份数
   ↓
到点自动截止（或手动"停止收集"）
   ↓
点击"下载全部"获得 ZIP → 立即保存到本地 / 网盘
   ↓
确认 ZIP 完整后，可"删除"作业清理数据（或保留记录）
```

> **重要习惯**：在 Vercel 部署时数据不会持久（见第 8 节），**每轮收集结束后请立即下载 ZIP**。

### 3.4 ZIP 下载说明

- ZIP 文件名格式：`<作业名称>_<作业ID>.zip`
- 内部文件保留学生的原始文件名（不做任何重命名）
- 中午/中文文件名均正常支持
- 重复提交的学生只会保留最后一次的文件（因为保存时就已覆盖）

## 4. 学生端使用指南

### 4.1 访问上传页

打开老师发的链接 `http://<域名>/upload/<作业ID>`。

页面会显示：作业名称、截止时间、命名规范的正则原文、老师的示例说明（如果填了）。

### 4.2 提交文件

1. 点击 **「选择文件」**，选中自己的作业文件
2. 点击 **「提交作业」**，确认弹窗中点"确定"
3. 出现绿色提示 **「提交成功！重复提交时以最后一次为准」** 即完成

### 4.3 三种被拒绝的状态

| 页面提示 | 原因 | 学生该怎么办 |
|---|---|---|
| 该作业已停止收集 | 老师手动关闭了收集 | 联系老师重新开启 |
| 该作业已截止，无法提交 | 超过了截止时间 | 联系老师 |
| 文件名不符合规范，请按格式重命名后提交 | 文件名与正则不完全匹配 | **按页面顶部的正则和示例重命名文件后重新提交** |
| 文件为空，请选择有效文件 | 选择了 0 字节的空文件 | 检查文件是否损坏，换有效文件 |
| 页面不存在，请检查链接是否正确 | 作业 ID 不存在（404） | 检查链接是否复制完整 |

### 4.4 重复提交规则

- **允许重复提交**，无需任何申请
- 如果新文件与之前提交的**文件名完全相同** → 旧文件被直接覆盖
- 如果文件名不同 → 视为两份文件，都会保留

> 所以：改了内容请用**同名覆盖提交**；不小心交错了文件，请重命名成正确名字再交一次，并告知老师删除那份错的。

## 5. 正则表达式编写教程

### 5.1 基本原理

系统使用 Python `re` 模块的 `fullmatch()` 校验，即文件名必须**从第一个字符到最后一个字符完全匹配**整个正则。不需要自己写 `^` 和 `$`（写了也不冲突）。

### 5.2 常用语法速查

| 语法 | 含义 | 示例 |
|---|---|---|
| `[0-9]` | 一个数字 | 匹配 `5` |
| `[a-zA-Z]` | 一个英文字母 | 匹配 `z` |
| `\u4e00-\u9fa5` | 一个中文字符（配合 `[]`） | 匹配 `张` |
| `[0-9]{4}` | 恰好 4 个数字 | 匹配 `2024` |
| `[0-9]{2,4}` | 2~4 个数字 | 匹配 `007` |
| `+` | 前面的内容至少 1 次 | `[a-z]+` 匹配 `abc` |
| `*` | 前面的内容 0 次或多次 | |
| `.` | 任意一个字符 | |
| `\.` | 一个真正的点（转义） | 匹配 `.` |
| `\d` | 数字（等价 `[0-9]`） | |
| `\w` | 字母/数字/下划线/中文 | |
| `\|` | 或 | `pdf\|doc` 匹配 `pdf` 或 `doc` |

### 5.3 实用模板（可直接复制）

**① 学号_姓名_实验N.pdf**
```
^[0-9]{9}_[\u4e00-\u9fa5]{2,4}_实验[0-9]+\.pdf$
```
匹配：`121112202_张三_实验1.pdf`

**② 学号姓名实验（原文档示例格式）**
```
^202[0-9]{4}_[a-zA-Z]+_实验[0-9]+\..*$
```
匹配：`2024001_Alice_实验1.pdf`（注意此模板姓名只支持字母）

**③ 学号-姓名.docx 或 .pdf**
```
^[0-9]{9}-[\u4e00-\u9fa5]{2,4}\.(docx|pdf)$
```
匹配：`121112202-李四.docx`、`121112202-李四.pdf`

**④ 只限定后缀，不限定前面内容**
```
^.*\.(zip|rar|7z)$
```
匹配：任何 zip/rar/7z 文件

**⑤ 学号+姓名+任意后缀**
```
^[0-9]{9}[\u4e00-\u9fa5]{2,4}\..+$
```

### 5.4 编写要点

1. **点必须转义**：后缀名的 `.` 要写成 `\.`，否则"任何字符"都会匹配
2. **多后缀用 `()` 和 `|`**：`\.(pdf|docx|doc)$`
3. **中文名用 `[\u4e00-\u9fa5]`**，别用 `.` 否则任何字符都能过
4. **发布前先自测**：把预期正确的文件名和几个错误文件名在心里"对一遍"；更保险的办法是发布后自己点"查看上传页"，先传一个正确命名的文件试水
5. 语法写错时系统会在发布阶段直接报错拒绝（如未闭合的括号），不会产生坏作业

## 6. 部署到 Vercel

### 6.1 前置条件

- 一个 [Vercel](https://vercel.com) 账号（免费版即可）
- 安装 Node.js（为使用 Vercel CLI），或直接用 GitHub 集成（无需本地 Node）

### 6.2 方式 A：命令行部署（最快）

```bash
npm i -g vercel        # 安装 Vercel CLI（如未安装）
cd NJUST_HomeworkCollector
vercel login           # 首次使用需登录
vercel --prod          # 部署到生产环境
```

部署完成后 CLI 会输出一个 `https://<项目名>.vercel.app` 域名，访问它就是教师端首页。

### 6.3 方式 B：GitHub 集成（自动重新部署）

1. 把本项目推送到你的 GitHub 仓库
2. 打开 [vercel.com/new](https://vercel.com/new)，导入该仓库
3. Vercel 会自动读取根目录的 `vercel.json` 和 `requirements.txt`，直接点 **Deploy**

之后每次 `git push` 都会自动重新部署。

### 6.4 部署配置说明（已内置，无需修改）

`vercel.json` 内容：

```json
{
  "builds": [{ "src": "app.py", "use": "@vercel/python" }],
  "routes": [{ "src": "/(.*)", "dest": "app.py" }]
}
```

- 所有请求（`/`、`/upload/...`、`/task/...`）都路由给 `app.py` 中的 Flask 应用
- 程序检测到 Vercel 环境（`VERCEL` 环境变量）后，自动把数据目录切换到 `/tmp/homework_collector`（Vercel 上只有 `/tmp` 可写）

### 6.5 部署后自定义域名（可选）

Vercel 控制台 → 你的项目 → **Settings → Domains** → 添加自己的域名，按提示配置 DNS 解析。

## 7. 数据存储说明

| 数据 | 位置 | 说明 |
|---|---|---|
| 作业记录 | `tasks.json` | JSON 数组，每条含：`id`（作业ID）、`name`（名称）、`regex`（正则）、`deadline`（截止时间，ISO 格式）、`status`（open/closed）、`created_at`（创建时间）、`note`（给学生的说明） |
| 提交的文件 | `uploads/<作业ID>/` | 保留学生上传时的原始文件名 |

- **本地运行**：两个路径都在项目根目录下（已被 `.gitignore` 忽略，不会误提交到 git）
- **Vercel 运行**：都在 `/tmp/homework_collector/` 下，**每次冷启动/重新部署后清空**

`tasks.json` 手工编辑示例（可用来批量修改截止时间等）：

```json
[
  {
    "id": "a6c5cb3c7bde",
    "name": "实验一 报告提交",
    "regex": "^[0-9]{9}_[\\u4e00-\\u9fa5]{2,4}_实验[0-9]+\\.pdf$",
    "deadline": "2026-09-10T23:59",
    "status": "open",
    "created_at": "2026-08-31 23:46:13",
    "note": "正确示例：121112202_张三_实验1.pdf"
  }
]
```

> 手工编辑时注意：JSON 中反斜杠要写成 `\\`。

## 8. 重要限制与注意事项

### 8.1 Vercel 单文件大小上限 ⚠️

Vercel Serverless Functions 对**请求体总大小约 4.5MB** 有硬限制。超过该大小的文件上传会直接失败（通常返回 413/Function 错误）。

- ✅ 适合：PDF 报告、Word 文档、代码文件、小图片
- ❌ 不适合：大型 zip、视频、数据集

大文件场景请用本地局域网部署（第 2.4 节）或自有服务器。

### 8.2 Vercel 数据不持久 ⚠️

无状态限制（你已知悉并接受）：

- **冷启动**（一段时间无访问后函数休眠再唤醒）→ 数据可能丢失
- **重新部署** → 数据必定丢失

**铁律：每轮收集一结束（或截止/手动停止后），立刻点"下载全部"保存 ZIP。** 不要指望数据一直躺在服务器上。

### 8.3 无鉴权的风险

- 任何拿到教师端链接（即首页 `/`）的人都能发布/下载/删除作业
- 学生端链接可以转发，任何人都能提交文件（但必须满足命名规范）
- 建议不要把首页链接发到公开场合；班级群内使用一般风险可控
- 删除按钮有二次确认，但**没有回收站**，删了就是删了

### 8.4 截止时间的时区

- 截止时间按**服务器本地时间**比较：
  - 本地运行 = 你电脑的时区
  - Vercel 运行 = **UTC 时区**（比北京时间慢 8 小时）
- 部署到 Vercel 后，如果学生都在中国，建议把截止时间**按 UTC 填写**，或直接填晚 8 小时的时间。例如希望北京时间 9 月 10 日 23:59 截止，应填 `09-10 15:59`

## 9. 常见问题（FAQ）

**Q1：学生说文件名明明是对的却被拒绝？**
A：检查是否真的完全匹配——最常见的原因：①多了空格或括号（如"张三 (1).pdf"）；②中文/英文标点混用（`（）` vs `()`）；③后缀大小写不匹配（正则写 `.pdf` 但文件是 `.PDF`，可在正则中加 `(?i)` 忽略大小写，或写成 `\.(pdf|PDF)`）；④学号位数不对。让学生对照页面顶部的正则原文逐字符检查。

**Q2：学生提交了错误文件名的文件，能帮他改吗？**
A：教师端没有改名单个文件的功能。两种做法：①让学生用正确文件名重新提交（同名错误文件不会被覆盖，会两份并存）；②下载全部 → 在本地手动整理。

**Q3：不小心删除了作业，能恢复吗？**
A：不能。删除会同时清掉记录和文件。如果之前下载过 ZIP，文件还在本地，但作业需要重新发布并重新发链接。

**Q4：部署到 Vercel 后学生提交失败，提示函数错误？**
A：大概率是文件超过 4.5MB 请求体上限，或所有学生集中提交触发限流。前者只能换更小的文件或本地部署；后者让学生错峰重试。

**Q5：截止前学生还能提交，截止后我还能下载吗？**
A：能。截止只封锁学生端的提交入口，教师端的下载、列表等全部功能不受影响，随时可下载。

**Q6：我能修改已发布作业的正则或截止时间吗？**
A：页面暂不支持，但可以直接编辑 `tasks.json`（本地部署时）后刷新页面。Vercel 上编辑没有意义（临时文件系统）。建议发布前把正则测好。

**Q7：`python app.py` 报错 `ModuleNotFoundError: No module named 'flask'`？**
A：没装依赖或没激活虚拟环境。执行 `pip install -r requirements.txt`，并确认虚拟环境已激活。

**Q8：原来的单页版还在吗？**
A：在 `legacy/` 目录下，含原 `homework_submit.py` 和旧模板，仍可按原 README 的 Nginx+uWSGI 方式独立运行，与新系统互不影响。

## 附录：路由一览

| 路由 | 方法 | 说明 |
|---|---|---|
| `/` | GET / POST | 教师端首页（GET 列表 / POST 发布） |
| `/upload/<作业ID>` | GET / POST | 学生端（GET 上传页 / POST 提交文件） |
| `/task/<作业ID>/download` | GET | 下载该作业全部文件（ZIP） |
| `/task/<作业ID>/toggle` | POST | 切换 开启 ↔ 关闭 |
| `/task/<作业ID>/delete` | POST | 删除作业及全部文件 |
